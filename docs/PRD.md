## 1. 项目背景

### 1.1 是什么

一个供小群体共用的打卡网站。负责人设定每日任务和截止时间，成员在规定时间前提交文字与照片，全组进度实时公示在一面墙上，谁交了、谁没交、几点交的，一眼看到。

### 1.2 解决什么问题

熟人小圈子的互相督促散落在聊天软件里：今天谁早起了、谁读书了，靠人肉接龙，几天就断。断的原因是**没有截止时间，也没有公开的进度**。这个产品把两件事固定下来——到点必须交，交没交所有人看得见。

### 1.3 不做什么（范围边界）

| 不做 | 原因 |
|---|---|
| 对外开放注册 | 只服务一个组，靠邀请码进入 |
| 排行榜、积分、等级 | 公示已经足够，排名会把「小事」变成攀比 |
| 私信、评论、好友关系 | 不在需求内 |
| ~~多组管理、组成员切换组~~ | **v0.5 作废**：已支持一人多组，见 4.10 |
| 原生 App / 小程序 | 网页即可，手机和电脑共用一套页面 |
| 数据回收站 | 删除即永久，与 v0.1 一致 |

## 2. 角色

v0.2 新增角色体系。三个角色，权限自上而下。

| 角色 | 数量 | 怎么来 | 能做什么 | 能不能被撤 |
|---|---|---|---|---|
| **站长**（owner） | 1 人，建组者 | 创建组时自动成为 | 全部权限，含指定/**收回**负责人、改任何设置 | **不能**。站长身份不参与交接 |
| **负责人**（leader） | **不限，可多人**（v0.5.5） | 由站长指定（可连续指定多个），或现任负责人交接 | 管任务、管截止时间、管提醒、发通知、导出、看总结、豁免个别成员、交接 | 能。站长逐个取消，或主动交接后仍保留 |
| **教师**（teacher，v0.5.3 新增） | 不限 | 用**教师码**加入，或由站长在成员详情里设 | 与负责人**完全相同**的管理权限；**不需要打卡**；**不计入任何统计** | 能（降回成员或停用） |
| **成员**（member） | 其余人 | 邀请码加入 | 打卡、看墙、看进度、点赞、加自定义小事（若开放）、导出日历 | — |

**关键规则**

1. 站长与负责人是**两个独立身份**，可以同一个人，也可以不同人。
2. 交接只交接「负责人」这个职责，**站长权限不受交接影响**，始终保留。这是用户明确要求（2026-11-06：「我作为管理员始终有权限」）。
3. 站长可以**直接指定、更换或收回负责人**，不需要对方确认，立即生效（v0.5：不再要求设 PIN）。
4. 负责人自己交接给别人时，**必须对方点「接受」才生效**，防止把职责推给不想接的人。
5. 交接完成后，上一任负责人**立刻**失去管理入口，无需等待或二次操作。
6. **负责人可以多个**（v0.5.5 变更）。站长连续指定即可累加；取消时按人取消，不影响其他人。
7. 站长收回负责人时，该组**未处理的交接请求一并作废**，防止对方事后接受把收回顶掉；组内暂时没有负责人时，管理权由站长代管。
8. 交接的**目标不能是站长**——`users.role` 是单值，若站长的行被改成 leader，站长身份就丢了。

## 4. 功能需求

### 4.1 加入、登录与设备

**登录方式（v0.6 变更，2026-11-14；推翻 v0.4 的手机/邮箱验证码）**

2026-11-14 起不再使用 WorkBuddy 托管云，迁到自己的 Supabase 项目。原来的邮箱验证码是平台能力，迁不走；在 Supabase 上继续用验证码会被「自带邮件服务每小时 2 封」卡死（9 个人当天聚不齐）。

因此登录改为：**邮箱 + 密码，注册与登录合一**——同一个表单，第一次填就是注册，之后填就是登录。没有验证码、没有手机号入口、没有微信授权。

| 步骤 | 内容 |
|---|---|
| 1 | 打开网站 → 填邮箱 + 密码（≥6 位）→ 点「进入」 |
| 2 | 没这个账号就自动建号并直接登录；已有账号密码错会提示 |
| 3 | 若还没进组 → 选「创建新组」／「用邀请码加入」／「教师加入」 |
| 4 | 填组名或邀请码 + 昵称 → 进入「今日」 |

**注册即确认**：不要求点邮件里的确认链接（Supabase 的 Confirm email 关闭；另用数据库触发器兜底，见 `sql/05-autoconfirm.sql`）。
**忘记密码**：找站长在 Supabase 控制台重置。不做自助邮件重置——同受免费邮件限流，且偶发需求不值得引入回跳流程。

**再次进入**：会话保存在浏览器，打开直接进入；多设备可同时在线，不互踢。
**换设备**：用同一组邮箱密码登录，身份自动对应。

**代价（明确接受）**：邮箱不再验证真实性，任何人都能注册一个空账号。但没邀请码就进不了任何组，读不到任何数据（行级权限按组过滤），等于空壳，因此不构成风险。

**规则表**

| 项 | 规则 |
|---|---|
| 邀请码 | 6 位大写十六进制，全局唯一，建组时生成，站长可改 |
| 教师码 | 6 位，与邀请码互不碰撞；用教师码加入即 `teacher` 角色 |
| 昵称 | 2–12 字符，组内唯一，可改（改后历史记录跟着变） |
| 会话 | 由 Supabase Auth 维护，退出登录即清除 |
| PIN | ~~4–6 位数字~~ v0.5 作废，不做管理入口 PIN |

### 4.2 今日（打卡主页面）

**页面构成**

| 区块 | 内容 |
|---|---|
| 顶部 | 日期、我的连续天数、今日完成 x/y、未读提醒红点 |
| 倒计时提醒条 | 最近一个将截止的任务，显示「还剩 xx」 |
| 任务列表 | 每项：图标、标题、截止时间、倒计时标签、我的状态 |
| 我的自定义小事 | 当天自己加的小事，同样可打勾 |
| 加一件小事 | 底部按钮，仅在「允许成员自定义」开启时出现 |
| 补记入口 | 日期切换，只能回看最近 3 天 |

**倒计时三档**

| 剩余时间 | 颜色 | 表现 |
|---|---|---|
| > 60 分钟 | 灰 | 静态文字 |
| 10–60 分钟 | 橙 | 静态文字 |
| < 10 分钟 | 红 | 文字 + 轻微呼吸动画（2s 循环，不做闪烁） |
| 已过截止 | 深灰 | 显示「已截止，可补记」 |

**打卡流程**

1. 点任务右侧圆圈 → 底部弹层升起
2. 弹层内：文字输入（≤200 字，可选）、照片选择（≤3 张，可选）
3. **文字与照片至少有一样**，否则提交按钮不可用
4. 提交 → 记录写入 → 圆圈变实心 → 进度条 +1 → 弹层收起
5. 若已过截止时间 → 提交后状态为「补记」，卡片上带灰色标记

**编辑与删除（只能动自己的）**

| 操作 | 规则 |
|---|---|
| 入口 | 今日页点实心圆打开编辑弹层（v0.5.1） |
| 编辑文字 | 随时，≤200 字 |
| 增删照片 | 随时，总数仍 ≤3 张 |
| 删除整条 | 编辑弹层内「删除整条」，二次确认，连同照片一起删 |
| 时间限制 | **没有**。截止前后都能改、都能删 |
| 对统计的影响 | 编辑不改完成时间与状态，按时率、完成率不变；删除即视为没交，该格变「未完成」 |

**负责人改状态（v0.5.4）**

| 项 | 规则 |
|---|---|
| 入口 | 打卡墙点开某条 → 详情弹层底部「改为按时」/「改回补记」 |
| 谁能用 | 负责人、站长、教师 |
| 范围 | 只能改**任务类**打卡；自己的也能改（用户 2026-11-09 明确要求）；豁免状态不在可改范围 |
| 影响 | 立即改变该条的按时/补记标记，按时率随之变化 |

删除不可恢复。负责人看到的是结果，不做二次审批。

**边界**

- 跨天以 **Asia/Shanghai 0 点**为界
- 补记：只能补最近 3 天（含今天）；更早的不能再新建，但自己的旧记录随时可编辑或删除
- 无网络：顶部提示「离线」，禁止提交，避免半截数据

### 4.3 打卡墙

**页面构成**

- 顶部：今天 / 本周 切换，成员头像条（谁交了谁没交）
- 主体：便签流（C 风格），两列瀑布，按完成时间倒序
- 每张便签：照片（可选）、文字、昵称、时间、点赞数、任务名
- 点便签 → 详情弹层：大图、全文、时间、点赞人列表

**规则**

| 项 | 规则 |
|---|---|
| 显示范围 | 只显示已完成的打卡 |
| 排序 | done_at 倒序 |
| 自己的 | 标「你」，**可以给自己点赞**（v0.5 变更） |
| 点赞 | 同一人对同一条只能点一次，可取消 |
| 照片 | 点击全屏，左右滑动切换同一条的多张 |
| 本周视图 | 按天分组，每天一个小标题 |

---

### 4.4 进度公示

**页面构成**

- 顶部汇总：今日应打卡 x 人、已完成 y 人、按时率 z%
- 矩阵表：行 = 成员，列 = 任务，格子 = ✓ / 补 / 空 / 免
- 底部：复制进度、一键提醒（仅负责人）、导出（仅负责人）
- 刷新：每 15 秒自动拉取（v0.5.1 已实现：页面可见、无弹层、输入框没聚焦时才拉）

**格子状态**

| 符号 | 含义 | 颜色 |
|---|---|---|
| ✓ | 按时完成 | 主色（薄荷绿） |
| 补 | 逾期补记 | 橙 |
| 空 | 未完成 | 浅灰虚线 |
| 免 | 负责人豁免 | 蓝灰 |

**一键复制**

点「复制进度」→ 生成下面的纯文本写入剪贴板，并提示「已复制」。

### 4.5 提醒

**两类提醒**

| 类型 | 触发 | 谁可设 |
|---|---|---|
| 定时提醒 | 每条任务截止前 N 分钟自动发 | 负责人逐条设（5–240 分钟，默认 30） |
| 一键提醒 | 负责人手动点，立刻发 | 负责人、站长 |

**落地状态（v0.5）**

| 通道 | 状态 | 说明 |
|---|---|---|
| 站内通知 | **已实现** | `pg_cron` 每分钟扫描并写入 `notifications`；打开页面时铃铛显示红点 |
| 手机日历（.ics） | **已实现**，见 4.5.3 | 导出日历文件，导入后由手机系统每天提醒，完全脱离网站 |
| 企业微信群机器人 | **手动已通，定时未做** | 点「催一下」时浏览器直接 POST 到机器人地址（`no-cors`，能发不能读回执）；定时自动推送仍需外部 Worker，原因见下 |

**投递规则（站内通知）**

- **站内通知**：写入 notifications 表，用户下次打开看到红点与横幅。这是兜底，永远发
- **企业微信机器人**：云函数 POST 到群机器人 webhook，群里出现一条消息并 @所有人
- 两个通道同一条提醒只发一次，不重复
- 已完成的人不再收到该任务的提醒
- 同一条任务同一天对同一人只发一次，避免轰炸

**机器人配置（暂缓）**

1. 负责人在企业微信群里添加一个群机器人，复制 webhook 地址
2. 管理 → 提醒 → 粘贴地址 → 点「发一条测试」确认群里能收到
3. 地址存在 `groups.wecom_webhook`，只有负责人与站长能改
4. 发送失败（地址失效、被限流）→ 自动退回只发站内，并在管理页留一条错误记录，不静默失败

**通知内容**

```
【该打卡了】日精进 23:50 截止，还剩 20 分钟
你今天的「日精进」还没提交。未完成：阿珍、七喜、大熊
```

### 4.5.3 手机日历提醒（.ics）

**解决的问题**：网页无法设置系统闹钟；站内通知要有人打开页面才看得到。导出日历文件后，提醒责任交给手机系统，不依赖任何人打开网页。

| 项 | 规则 |
|---|---|
| 入口 | 「我的」页（**全部成员可见**）、「管理」页（负责人/站长，方便导出发群） |
| 内容 | 每个未归档任务一条事件，每天重复（`RRULE:FREQ=DAILY`） |
| 时间 | 统一写 UTC 绝对时间，不带时区块——中国无夏令时，绝对时间永远准 |
| 提醒 | `VALARM` 提前量取任务自身的 `reminder_offset`；为 0 的任务不带闹钟 |
| 去重 | `UID` 取 `task.id`，重复导入覆盖同一条，不堆叠 |

**分发方式**：一个人导出后发到群里，其他人各自点开、确认添加到日历。日历是本地数据，网站无法写入他人手机。

**已知限制**

1. 日历是导入时的快照，与网站彻底断开：改任务要重新导入；删掉的任务不会自动消失，需自行在日历里删除。
2. 微信内置浏览器常无法打开 .ics，需用 Safari / Chrome 打开。

**为什么暂缓企业微信群推送**

数据库只能装 `pg_cron`，没有 `pg_net`，无法自发 HTTP。可行方案是加一个外部转发服务（Cloudflare Workers 免费额度远够用），但得取舍：

- 由网页触发 → 能点名谁没交，但没人在线时不会发；
- 由 Worker 自带定时器 → 准时，但读不到数据库，只能发不点名的泛提醒。

`groups.wecom_webhook` 字段与管理入口保留，未来补上 Worker 即可启用。

### 4.6 统计与智能总结

**基础指标（规则计算，不依赖模型）**

| 指标 | 定义 |
|---|---|
| 应完成数 | Σ（统计区间内每天的生效任务数 × 成员数）− 豁免数 |
| 按时率 | 按时完成数 ÷ 应完成数 |
| 完成率 | （按时 + 补记）÷ 应完成数 |
| 连续天数 | 从今天往前，每天至少有 **1 条打卡**（按时或补记均可）即算连续；今天没交则从昨天起算 |
| 成员维度 | 每人的按时率、完成数、最常缺的任务 |
| 任务维度 | 每项任务的按时率、平均完成时间 |
| 异常提示 | 连续 3 天未打卡的人；按时率低于 50% 的任务 |

**智能总结**

- 负责人选时间范围（最近 7 天 / 本月 / 自定义）→ 点「生成总结」
- 输出结构：一段 200–300 字的整体描述 + 上面的指标表 + 异常清单
- 文字部分由大模型生成，**只陈述事实与异常，不做评价、不用夸张比喻**
- 模型调用经云函数代理，密钥不下发前端；模型不可用时自动降级为纯规则版

### 4.10 一人多组（v0.5 新增）

一个账号可以同时属于多个组。切组即换身份与数据，组间完全隔离。

| 项 | 规则 |
|---|---|
| 进入方式 | 首次登录且不属于任何组时，进「创建新组 / 用邀请码加入」页 |
| 再开一组 | 「我的」→「我的组」→ 创建新组 / 用邀请码加入；建完自动切过去，原组保留 |
| 切换 | 「我的」→「我的组」→ 点另一个组，立即生效并重新加载该组数据 |
| 身份 | 每个组的角色独立。在 A 组是站长，在 B 组可能只是成员 |
| 昵称 | 按组独立，同一个组内仍唯一 |
| 数据 | 任务、打卡、点赞、通知、交接全部按组隔离 |
| 当前组 | 每个账号在库里有且只有一个「当前组」标记，用于行级权限判断 |

**实现要点**（供接手者参考）

- `users` 表：唯一约束从 `auth_uid` 改为 `(auth_uid, group_id)`；新增 `is_current` 布尔，配部分唯一索引保证一账号只有一个当前组
- `current_group_id()` / `current_role_name()` / `current_user_id()` / `is_admin()` 全部按「当前组」取，因此 27 条行级策略无需逐条修改
- `switch_group(p_group_id)` 负责切组；`create_group` / `join_group` 不再限制「已在一个组」

## 7. 关键流程

### 7.1 一条打卡的状态变化

```
       提交（截止前）              截止时刻                +72 小时
  ────────────────●───────────────────●──────────────────────●────────
                  │                   │                      │
              on_time              仍未提交                不可再补
                                      ↓
                              可补记（late），带「补」标记
                                      ↓
                              负责人可改为 excused（豁免）
```

- 豁免（excused）不计入分母，也不计入完成数
- 补记（late）计入完成率，不计入按时率
- 超过 72 小时，格子锁死为「未完成」

### 7.2 交接

```
负责人点「交接」→ 选人 → 生成 pending
        ↓
对方登录看到请求 → 接受（v0.5：不再要求确认 PIN）
        ↓
事务内：groups.leader_id = 新负责人
        users.role：旧负责人 → member，新负责人 → leader
        handovers.status = accepted
        ↓
旧负责人刷新页面，管理入口消失
```

站长不受影响；若站长本人是负责人，交接后仍是站长。

## 10. 技术形态

> v0.6（2026-11-14）整体换过一层：从 WorkBuddy 托管云迁到自有 Supabase，并加了同源反代。
> 迁移的来龙去脉见 `.workbuddy/memory/2026-11-14.md`。

| 层 | 方案 |
|---|---|
| 前端 | 原生 HTML/CSS/JS，无框架、无构建；设计令牌 + 三档断点 |
| 部署 | **Node 单端口服务 `server.js`**：静态文件（自己 gzip）+ `/sb/*` 反代到 Supabase，无 npm 运行时依赖 |
| 数据 | 自有 Supabase（PostgreSQL 17），10 张表，RLS 全开，16 个 `SECURITY DEFINER` 函数 |
| 认证 | Supabase Auth：邮箱 + 密码，注册与登录合一；注册即确认（`sql/05`） |
| 文件 | Supabase Storage 私有桶 `shared`，签名链接 1 小时；前端压缩后直传（1280/0.72 + 400px 缩略图） |
| 定时 | pg_cron 每分钟执行 `enqueue_due_reminders()`（无 JWT 时扫全组） |
| 提醒 | 站内写 notifications 表；日历导出 .ics 本地生成；企微群机器人由浏览器直发 |
| 模型 | 迁移后**不再调用平台模型**，周报总结改由前端规则生成（原平台能力已不可用） |
| 导出 | 浏览器本地生成，四种格式都不经过服务器 |
| 仓库 | GitHub，每完成一个功能 commit + push，直接推 main |

**已知风险**

| 风险 | 影响 | 应对 |
|---|---|---|
| 国内直连 Supabase 不通 | 手机登录报 `Failed to fetch` | 已用同源反代解决；代价是全站依赖 `server.js`，不能再退回纯静态托管 |
| 平台 Edge 改写 `Authorization` | JWT 验签失败（PGRST301） | token 走自定义头 `x-sb-auth`，服务器还原（见 AGENTS.md 第二节） |
| 免费额度：照片 1 GB | 约 8–10 个月满（9 人用量） | 已压小并加缩略图；到期前做 90 天清理或升 Pro |
| 免费项目 7 天无人访问会休眠 | 打开变慢 | 组内天天打卡，不会触发；真休眠了控制台点一下恢复 |
| 前端生成 docx 遇大量照片 | 卡顿或内存溢出 | 限制单次 92 天、照片缩略图 320px |
| 企微机器人需成员在群 | 有人收不到 | 站内通知兜底 |
